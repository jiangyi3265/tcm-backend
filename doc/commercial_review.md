## 📊 项目总览

本项目是一个**中医诊所综合管理系统（TCM Clinic Management System）**，包含两个主要部分：

| 组件 | 技术栈 | 说明 |
|------|--------|------|

| **RuoYi-Vue** (若依后端) | Spring Boot + MyBatis + MySQL | 管理后台框架（TCM扩展模块） |

## 🔴 严重问题（必须修复才能商用）

### 1. 数据库使用 H2 嵌入式数据库 ⚠️⚠️⚠️
**文件**: `server/src/main/resources/application.properties:4`
```properties
spring.datasource.url=jdbc:h2:file:./data/clinicdb
```
**问题**: H2 是开发/测试用的嵌入式数据库，**不适合生产环境**：
- 不支持并发写入（同一时间只允许单个写操作）
- 数据文件损坏风险较高
- 无法分布式部署

**建议**: 必须切换到 **MySQL/PostgreSQL** 等生产级数据库。

---

### 2. JWT 密钥硬编码 ⚠️⚠️⚠️
**文件**: `application.properties:22`
```properties
app.jwt.secret=${JWT_SECRET:TCMClinicSecretKey2024VeryLongSecureRandomStringForHS256Algorithm}
```
**问题**: 默认密钥直接暴露在代码中，若部署时忘记设置环境变量，任何人都可以伪造JWT token。

**建议**: 
- 生产环境必须通过环境变量设置强密钥（32位随机字符串）
- 移除默认值，强制配置

---

### 3. CORS 配置为 `*` 全开放 ⚠️⚠️
**文件**: `WebConfig.java:32`
```java
.allowedOrigins("*")
```
**问题**: 允许任何来源的跨域请求，存在安全风险（CSRF等攻击）。

**建议**: 限制为你的前端域名，如 `allowedOrigins("https://your-domain.com")`

---

### 4. CSRF 已完全禁用 ⚠️
**文件**: `SecurityConfig.java:26`
```java
.csrf(csrf -> csrf.disable())
```
**问题**: 虽然 JWT 无状态认证下通常禁用 CSRF 是合理的，但需要确保所有API都通过 JWT 验证。

**现状**: 目前看起来是合理的（纯API架构），但需要确保公开端点（consent/intake）不会被滥用。

---

### 5. 演示密码仍保留在代码中 ⚠️⚠️
**文件**: `sampleData.js:70-126`
```javascript
export const DEMO_USERS = [
  { email: 'admin@clinic.com', password: 'admin123', ... },
  ...
]
```
**问题**: 
- `sampleData.js` 中包含硬编码的演示账户和密码
- `LoginView.vue` 上有 "一键登录" 演示按钮

**建议**: 
- 生产环境构建时移除或条件化 demo 数据
- 添加环境变量控制 demo 功能的显示

---

### 6. 密码明文兼容逻辑 ⚠️
**文件**: `AuthController.java:84`
```java
if (rawPassword.equals(storedPassword)) {
    user.setPassword(passwordEncoder.encode(rawPassword));
```
**问题**: 仍保留明文密码对比逻辑（用于从旧系统迁移）。商用后应移除这段代码，确保所有密码都已 BCrypt 加密。

## 🟡 需要改进的问题（建议修复）

### 7. 缺少数据验证和输入校验
**问题**: 
- 前端表单仅有简单的非空验证（如 `!form.email`）
- 后端 Controller 接收 `Map<String, String>` 没有使用 `@Valid` 真正做参数校验
- 缺少 SQL 注入防护（虽然 JPA 本身有一定防护）

**建议**: 
- 后端使用 `@Valid` + DTO 类进行参数校验
- 前端使用 Element Plus 的 `<el-form :rules>` 做表单验证

---

### 8. Bootstrap接口一次性返回ALL数据 ⚠️
**文件**: `BootstrapController.java:54-90`
```java
result.put("users", userRepo.findAll()...);
result.put("patients", patientRepo.findAll()...);
result.put("consultations", consultationRepo.findAll()...);
```
**问题**: 
- `/api/bootstrap` 接口一次性返回**所有**用户、病人、预约、诊疗、库存数据
- 当数据量增长到几千条记录时，这个接口会非常慢
- 所有数据存储在 `localStorage`，有 5MB 大小限制

**建议**: 
- 改为分页查询 + 按需加载
- 删除或改造 bootstrap 机制

---

### 9. 没有操作日志/审计跟踪
**问题**: 对于医疗系统，操作日志是必备功能。目前：
- 无法追踪谁在什么时间修改了什么数据
- 无法满足医疗行业的合规要求

**建议**: 
- 添加全局操作日志表
- 记录关键操作（创建/修改/删除 诊疗记录、处方、病人信息等）

---

### 10. 缺少数据备份方案
**问题**: 没有任何数据备份机制。H2 数据库文件仅在本地存储。

**建议**: 
- 迁移到 MySQL 后配置定期备份
- 添加数据导出功能

---

### 11. 缺少 HTTPS 强制
**问题**: 医疗数据属于敏感个人信息，必须使用 HTTPS 传输。当前配置没有强制 HTTPS。

**建议**: 
- 部署时在 Nginx 层面强制 HTTPS
- 后端添加安全头 (HSTS, X-Content-Type-Options 等)

---

### 12. 版本管理问题
**文件**: `package.json:3`
```json
"version": "0.0.0"
```
**建议**: 设置正式版本号（如 `1.0.0`），建立版本发布流程。
